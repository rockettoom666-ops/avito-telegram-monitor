# Платежи и коммерческий запуск

Бот поддерживает два встроенных счёта Telegram:

- **TG Stars** — счёт в валюте `XTR`;
- **ЮKassa** — счёт в рублях через платёжного провайдера Telegram.

Для подписки на мониторинг как цифровой услуги внутри Telegram используйте
**Stars**: этого требуют [правила Telegram](https://core.telegram.org/bots/payments-stars).
Ниже описана также существующая реализация ЮKassa; её наличие в коде не означает,
что она подходит для продажи цифровой подписки внутри Telegram.
Первый запуск и админ-доступ: [INSTALL.md](INSTALL.md), [ADMIN.md](ADMIN.md).

Тарифы:

- **Старт** — 2 поиска, 7 дней, 200 ₽ или 150 Stars;
- **Про** — 5 поисков, 7 дней, 350 ₽ или 250 Stars;
- **Навсегда** — 1 поиск без ограничения срока, проверки с интервалом
  15, 30 или 60 минут, 100 ₽ или 75 Stars.

Цены в Stars и бессрочного тарифа меняются через `BASIC_PLAN_STARS`, `PRO_PLAN_STARS`,
`LIFETIME_PLAN_RUBLES` и `LIFETIME_PLAN_STARS` в `.env`. Недельные рублёвые цены
200/350 ₽ заданы в `src/avito_bot/plans.py`. Автоматического
продления нет. Повторная обработка одного номера платежа не продлевает
подписку второй раз.

```dotenv
LIFETIME_PLAN_RUBLES=100
LIFETIME_PLAN_STARS=75
```

Бессрочный доступ хранится отдельным признаком в базе и сохраняется после
перезапуска. Если поверх него купить недельный тариф, временно применится
лимит недельного тарифа, а после его окончания снова останется один поиск с
минимальным интервалом 15 минут.

## Подключение ЮKassa

Для интеграции из официальной инструкции не нужны прямые запросы к API ЮKassa,
`shopId` и секретный API-ключ. Нужен **provider token от BotFather**:

1. Откройте `@BotFather` и отправьте `/mybots`.
2. Выберите своего бота.
3. Откройте **Payments**.
4. Для проверки выберите **Connect ЮKassa: тест**, для настоящих платежей —
   **Connect ЮKassa: платежи**.
5. Авторизуйтесь в ЮKassa и разрешите доступ к нужному магазину.
6. Вернитесь в BotFather. Скопируйте показанный платёжный токен.
7. Добавьте его в локальный `.env`:

```dotenv
YOOKASSA_PROVIDER_TOKEN=токен_из_BotFather
YOOKASSA_SEND_RECEIPT=true
YOOKASSA_VAT_CODE=1
YOOKASSA_TEST_PRICE_RUBLES=88
ADMIN_CHAT_IDS=123456789
```

`YOOKASSA_VAT_CODE=1` означает «без НДС». Если у продавца другая ставка,
нужно указать соответствующий код. Токен нельзя публиковать, добавлять в Git
или присылать клиентам.

Для совместимости бот временно распознаёт provider token, который в старой
версии был ошибочно вставлен в `YOOKASSA_SECRET_KEY`. Рекомендуется всё равно
переименовать переменную в `YOOKASSA_PROVIDER_TOKEN`.

Официальная инструкция:
[настройка Telegram-платежей ЮKassa](https://yookassa.ru/docs/support/payments/onboarding/integration/cms-module/telegram).

В этой интеграции ЮKassa указывает банковские карты, ЮMoney и SberPay.
СБП не следует считать гарантированно доступным способом: для дополнительных
методов ЮKassa предлагает отдельную интеграцию через свой API.

## Чеки

Если в магазине подключены **Чеки от ЮKassa**, оставьте
`YOOKASSA_SEND_RECEIPT=true`. Тогда счёт:

- запрашивает e-mail покупателя;
- передаёт e-mail провайдеру;
- отправляет в `provider_data` позицию чека, сумму, предмет расчёта и код НДС.

ЮKassa предупреждает, что без этих данных платёж при включённых чеках может
завершиться ошибкой. Если фискализация полностью выполняется вашей собственной
кассой, установите `YOOKASSA_SEND_RECEIPT=false` и настройте выдачу чеков по
правилам своей налоговой схемы.

## Как бот подтверждает оплату

1. Кнопка ЮKassa вызывает Telegram Bot API `sendInvoice` с `provider_token`,
   валютой `RUB` и ценой в копейках.
2. На `pre_checkout_query` бот отвечает сразу, проверив пользователя, тариф,
   валюту и сумму.
3. Подписка активируется только после `successful_payment`.
4. Для ЮKassa в базе сохраняется `provider_payment_charge_id`, по которому
   транзакцию можно найти в личном кабинете.

Ручная кнопка «Проверить оплату» не нужна: успешный результат приходит боту
автоматически через Telegram.

## Тестовая оплата для администраторов

В `ADMIN_CHAT_IDS` указываются Telegram ID администраторов. Несколько ID
разделяются запятыми:

```dotenv
ADMIN_CHAT_IDS=123456789,987654321
```

Каждый указанный администратор автоматически получает вечный доступ с
максимальным лимитом поисков (`MAX_SUBSCRIPTIONS_PER_USER`) и интервалами от
2 минут. Доступ назначается при каждом запуске, поэтому тестовая покупка его не
уменьшит. Чтобы убрать льготу, удалите ID из `.env` и перезапустите бот.

Только этим аккаунтам после выбора тарифа показывается кнопка
**«🧪 Тест ЮKassa — 88 ₽»**. Она выставляет настоящий счёт через тот же
`provider_token`, а после успешной оплаты активирует выбранный тариф. Проверки
`pre_checkout_query` и `successful_payment` дополнительно сверяют, что
покупатель входит в `ADMIN_CHAT_IDS`. Поэтому обычный пользователь не сможет
вызвать тестовую цену даже через поддельный `callback_data` или `payload`.

В этой версии код не позволяет установить `YOOKASSA_TEST_PRICE_RUBLES` ниже
88 ₽. Это ограничение реализации, основанное на лимите, проверенном при её
создании. Актуальные лимиты валют проверяйте в
[списке Telegram](https://core.telegram.org/bots/payments/currencies.json).
Тестовая кнопка с боевым provider token списывает настоящие деньги; для
проверки без списания используйте тестовое подключение провайдера.

Узнать свой Telegram ID можно командой `/id` в личном чате со своим ботом.

## Telegram Stars

Счёт Stars использует `currency="XTR"` и пустой `provider_token`. Бот также
проверяет `pre_checkout_query` и активирует тариф только после
`successful_payment`.

Telegram требует использовать Stars для цифровых товаров и услуг внутри своих
приложений. Перед публичным запуском варианта оплаты в рублях проверьте, что
ваш сценарий соответствует актуальным правилам Telegram и условиям ЮKassa:
https://core.telegram.org/bots/payments-stars

Перед запуском заполните также:

- `MERCHANT_NAME` — имя продавца, ИП, ООО или самозанятого;
- `SUPPORT_CONTACT` — контакт для вопросов об оплате и возвратах.
